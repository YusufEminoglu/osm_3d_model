OSM 3D Model

One-click OpenStreetMap to interactive Three.js 3D city viewer • v1.2.0

1. Overview

OSM 3D Model is a single-click QGIS-to-browser pipeline that downloads live OpenStreetMap data for a user-defined study area and opens an interactive Three.js 3D city viewer. The plugin handles the entire data pipeline—Overpass API download with multi-mirror fallback and 7-day disk cache, OSM tag parsing into 10 memory layers, GeoJSON export with a manifest, and a local HTTP server that launches the browser-based PlanX 3D City engine. The viewer renders procedural buildings with roofs, roads with lane markings and animated traffic, sidewalks with pedestrians, trees, street furniture, water features, and optional DEM terrain and basemap underlay.

The plugin operates as a toolbar-activated dialog. It has no processing provider integration. All processing is on-demand and non-destructive: source OSM data is never modified.

2. Feature Documentation

2.1 Study Area Definition

Area Sources and Boundary Shapes

Two area sources: Current map extent (canvas) or Selected polygon features (active vector layer). Four boundary shapes: Circle (largest inscribed circle, default), Rounded rectangle (corner radius ~16% of short side), Extent (plain bounding box), and Polygon (exact selected geometry). The area is auto-reprojected to its local UTM zone and clamped to a configurable maximum size (default 150 ha).

All shapes include a 5 m presentation platform extending beyond the clip boundary with rounded corners.

2.2 OSM Data Download

Overpass API Pipeline

Queries Overpass API for buildings, highways, cycleways, waterways, water areas, green spaces, parking lots, pedestrian squares, trees, bus stops, benches, street lamps, and waste baskets. Three mirror endpoints (overpass-api.de, overpass.kumi.systems, overpass.private.coffee) are tried in order. Responses are cached in %TEMP%/osm_3d_model_cache/ with a 7-day TTL keyed by SHA-256 of the query string.

2.3 Layer Types

Exported Data Layers

Ten memory layers are created and exported as GeoJSON: OSM Buildings (MultiPolygon, with building type, levels, height, footprint, and GFA columns), OSM Roads (MultiLineString, with highway class and width), OSM Bike lanes, OSM Greens (MultiPolygon, including parks, forests, cemeteries, parking lots, and pedestrian plazas), OSM Waterways (MultiLineString), OSM Water areas (MultiPolygon), OSM Trees (Point), OSM Bus stops (Point), OSM Benches (Point), OSM Street lights (Point), and OSM Trash bins (Point).

2.4 Three.js Viewer

Scene Composition

The browser viewer renders: procedural buildings with roof styles (pyramid, gable, hip, shed, flat) and 4 facade textures; roads with lane markings, sidewalks, and bike lanes; animated traffic (cars, vans, buses, trucks) and pedestrians; procedural trees (instanced, with multiple variant profiles); street furniture aligned to roads; water areas and linear waterways; optional DEM terrain and basemap underlay; and a model base island with configurable drop and color.

2.5 Viewer Panels

Dock Panel System

The viewer provides 8 panel types: Dashboard (scene metrics and data health), Layers (per-category visibility toggles), Style (building modes, roof shapes, facade textures, tree render modes), Scene & Sun (time-of-day slider, weather, fog, SSAO, bloom, traffic density), Model Studio (custom GLB model upload by furniture category), Basemap & Texture (opacity, blend mode, shadow catching), Export Studio (PNG/JPEG/WebP/PDF/SVG/HTML stills, WebM/MP4 video recording, clipboard copy), and Walk Mode (first-person WASD navigation at pedestrian eye height).

2.6 Color Themes

Eleven Coordinated Palettes

Editorial Paper (default, warm ivory), Plugin Tones (salmon and grey), Tinted Gray Teal, Teal & Salmon, Light Purple & Black, Warm Sand & Slate, Anime (bright cel-shaded pastels), Cartoon (bold primaries), Pixar (warm creams and oranges), Futuristic City (dark neon with cyan/violet glass), and Classic Era (vintage sepia with terracotta roofs). Themes set coordinated colors for the island base, terrain, roads, parks, water, roof texture, and asset theme.

4. Workflow Guide

  1. Pan and zoom the QGIS canvas to the desired study area, or select polygon features representing the boundary.
  2. Click the OSM 3D Model toolbar icon to open the dialog.
  3. Optionally click Add OSM basemap to the map for a reference tile layer.
  4. Choose the area source, boundary shape, and max area. The live area readout shows estimated hectares.
  5. Select a theme from the dropdown (affects both QGIS layer styling and 3D viewer colours).
  6. Optionally expand Advanced to add a DEM raster or basemap layer.
  7. Click Create OSM layers & export 3D viewer. The plugin downloads OSM data, processes it, exports GeoJSON, and opens the viewer in the default browser.
  8. In the viewer, use the toolbar to open panels for layer visibility, styling, time-of-day, export, and walk mode.
  9. The export result is also added as a styled QGIS layer group named "3D OSM Model" for inspection and further analysis.

5. Technical Notes

  • CRS handling: The study area centroid is projected to a local UTM EPSG code. All geometry processing and clipping uses metric coordinates.
  • Multipolygon assembly: OSM relations are stitched into multipolygons with proper outer/inner ring handling for buildings with courtyards.
  • Tree scattering: A deterministic LCG-based PRNG seeds tree placement from polygon footprint coordinates, producing identical results on re-runs.
  • Server security: Local HTTP server binds to 127.0.0.1 only, sends same-origin CORS policy, Cache-Control: no-store, and X-Content-Type-Options / X-Frame-Options security headers.
  • Atomic GeoJSON publish: Files are written to a staging directory and atomically published with backup on failure.
  • Viewer architecture: Three.js with ES module imports, WebGLRenderer with shadow mapping, EffectComposer with UnrealBloomPass, and OrbitControls. Settings persist in IndexedDB. Scene rebuild tokens abort stale rebuilds.
  • QGIS compatibility: 3.28 through 4.99. Pure qgis.core / qgis.gui / qgis.PyQt with no external Python dependencies.
